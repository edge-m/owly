# Owly の哲学

Owly は、AI エージェントが書く Markdown Wiki を、チームで安心して育て続けるための構造基盤である。

Owly は知識の意味を理解したふりをしない。本文を検索する道具を作り直しもしない。人間が決めた構成を明示し、エージェントがその構成を守れているかを、速く、確実に確かめる。そのための道具である。

## 1. 知識基盤は、最初からスケールするように作る

Wiki は個人のメモで終わらない。記事が増え、AI エージェントが更新し、複数人が同時に扱う知識基盤になる。その前提で、Owly はファイル数・チーム・知識グラフの成長を設計に含める。

### Git をチームの共通基盤にする

Wiki は Git で管理する。履歴、差分、レビュー、復元、競合解消は、Wiki 専用の独自機構ではなく、チームがすでに使い慣れた Git のワークフローで扱う。

Markdown と `owly.yml` は Git が追跡する正本である。誰が、いつ、何を、なぜ変えたかを後から確認できることは、複数人と複数のエージェントが同じ Wiki を扱うための最低条件である。

### Graph を再帰的に分ける

1 つの巨大な Graph にすべての記事を置かない。一定の規模になった Graph は、ひとまとまりの知識領域として完結させる。

Graph の内部では記事どうしを自由に参照できる。一方、別の Graph を参照するときは、その Graph の入口だけを参照する。個別の記事へ直接つなげない。

```text
Graph A ──→ Graph B の入口 ──→ Graph B の内部
```

この境界により、Graph は局所的に検索・検証できる。さらに Graph は別の Graph を参照できるため、Graph of Graphs、Graph of Graphs of Graphs と必要に応じて再帰的に階層化できる。全体を 1 つに膨らませず、完結した Graph を増やすことでスケールする。

### 検索は SQLite のインデックスで支える

frontmatter の条件検索のために、検索のたびに Markdown ファイルを全走査しない。Owly は SQLite を検索インデックスとして使い、ファイル数が増えても構造化検索を効率よく行えるようにする。

SQLite は正本ではない。正本は Markdown と frontmatter であり、SQLite はそこから再構築できる派生データである。この分離によって、検索性能とファイルベースの可搬性を両立する。

## 2. 独自の世界を作らない

Owly は、すでに優れた道具がある領域を置き換えない。独自の概念や形式は、既存の道具では届かないところにだけ導入する。

### 本文は既存のツールで探す

本文の単語やフレーズを探すなら `rg`、`fd`、`grep`、エディタを使う。速く、普遍的で、パイプやスクリプトにも自然につながるからだ。

Owly が担当するのは、frontmatter の条件検索、文書タイプ、リンク、ソース、構成ルールの検証である。テキスト検索と構造検索を混ぜない。

### 構成は設定で定義する

Wiki の構成は固定しない。チームは `owly.yml` で、ディレクトリ、文書タイプ、必須フィールド、値の型、許可値、検証ルールを自分たちの領域に合わせて定義する。

Owly は、ファイル名や既存ページの雰囲気からルールを推測しない。設定に書かれたものだけを契約として扱う。これにより、利用者は自分たちの Wiki を自由に設計でき、エージェントは曖昧な慣習ではなく明示的なルールに従える。

### 本文の自由を守る

Owly は本文の意味、真偽、文体、文章品質を採点しない。検証するのは、チームが合意した構造上の契約だけである。

Markdown、YAML、SQLite、Git という理解しやすく移植しやすい技術の上に立ち、利用者は必要ならいつでもファイルを直接読み、一般的なコマンドで調べられる。Owly が Wiki を囲い込むことはない。

## 3. エージェントに任せ、検証は任せない

エージェントには、資料の読解、要約、分類、記事作成、リンク付けを任せる。大量の知識を更新する仕事は、エージェントが最も力を発揮する領域である。

ただし、エージェントの出力をそのまま信頼しない。必須フィールドの欠落、型の誤り、未知の文書タイプ、壊れたリンクは、確率的な生成を使う以上、自然に起きる。

Owly は、このための Linter である。

```text
人間が owly.yml を定義する
        ↓
エージェントが記事を書く
        ↓
Owly が構造を検証する
        ↓
診断をもとにエージェントまたは人間が修正する
```

Owly は frontmatter、文書タイプ、フィールド、リンク、孤立ページ、ソースを決定論的に検証する。同じ設定と同じファイルには、誰が実行しても同じ結果を返す。

そして Owly は、検証中にファイルを勝手に編集しない。検証と変更は別の責務である。変更は必ず人間、または人間が明示的に指示したワークフローが行う。

## Owly が守る境界

| 領域 | 担当 |
|---|---|
| 本文検索 | `rg` / `fd` / `grep` / エディタ |
| Wiki の構成 | 人間と `owly.yml` |
| 記事の作成・更新 | AI エージェントと人間 |
| frontmatter の構造化検索 | Owly と SQLite インデックス |
| 構成・リンク・ソースの検証 | Owly |
| 履歴・レビュー・競合解消 | Git |

Owly は、すべてを自分でやるためのツールではない。既存の道具と役割分担しながら、AI エージェントが書く Wiki の構造を、長期にわたって信頼できるものにする。
