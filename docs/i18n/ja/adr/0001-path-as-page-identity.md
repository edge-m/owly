# ADR 0001: パスをページの identity とする

- 状態: 採用
- 日付: 2026-08-29

## 文脈

Owly の Wiki ページは Markdown ファイルであり、ページ間の参照は本文中のパスに依存する。ファイル名から独立した永続 ID を frontmatter や SQLite に持たせる案もあるが、ファイルを移動・改名したとき、本文中に分散したリンクは結局すべて更新する必要がある。

ID だけを安定させても、Wiki 上の参照変更を局所化できない。また、Owly は本文の意味や編集を担当せず、検証と構造インデックスを担当する。

## 決定

Wiki ページの identity は、Wiki ルートからの正規化相対パスとする。ファイル名をまたぐ永続的なページ ID は持たない。

- `documents.path` をページの主キーとする
- `page_id` の別カラムは持たない
- ファイルの改名・移動は、旧パスのページが削除され、新パスのページが追加されたものとして扱う
- 旧パスへのリンクは `validate` で壊れたリンクとして報告する
- リンクの一括書き換えや改名の自動推測は Owly の責務にしない
- 同一内容の移動を検出できる場合も、`content_hash` はリネーム候補のヒントにとどめ、identity にはしない

## 結果

### 利点

- Markdown のリンクモデルと SQLite の identity が一致する
- DB の更新でリンク変更を隠せないため、壊れた参照を検出できる
- 永続 ID の採番、衝突、移行、同期処理が不要になる
- 正本のパスを直接読めばページを特定できる

### 代償

- 改名・移動時は、参照元 Markdown のリンクを更新する必要がある
- Git の rename 検出や content hash による候補提示は、必要なら別の保守機能として追加する
- 外部システムからページを参照する場合、パス変更で参照が壊れる

## 却下した案

ファイル名と独立した UUID をページに付与する案は却下する。UUID は DB 上では改名を一つの更新に見せられるが、Markdown に散在するリンクの更新問題を解決しないためである。
