# ADR 0002: Frontmatter の値を型別カラムに保存する

- 状態: 採用
- 日付: 2026-08-29

## 文脈

Frontmatter は Wiki ごとにフィールドが異なるため、フィールド名ごとに固定カラムを作ることはできない。一方、すべての値を文字列に変換すると、数値・真偽値・日付の意味が失われ、検索や並べ替えで誤った結果になる。

例として、数値を文字列で比較すると、辞書順によって `"10"` が `"2"` より前になる。`"true"` と `true` も、文字列としては同じに見えてしまう。

## 決定

`frontmatter_values` は可変な `field_path` と、値の型を表す `value_type` を持つ。値本体は型に応じた専用カラムへ保存する。

- `string` → `value_text`
- `number` → `value_number`
- `boolean` → `value_boolean`（`0` または `1`）
- `date` → `value_date`（正規化した ISO 8601 の日付文字列）
- `datetime` → `value_datetime`（UTC に正規化した ISO 8601 の日時文字列）
- `null` → 値カラムは `NULL`
- 配列・オブジェクトの元表現 → 必要に応じて `value_json`

各レコードでは、`value_type` に対応するカラムだけを非 NULL にする。検索インデックスは `field_path`、`value_type`、対応する型別カラムを組み合わせる。

## 理由

- 数値の大小比較・範囲検索・ソートを正しく行える
- 真偽値と文字列を区別できる
- 日付・日時の範囲検索を文字列変換に頼らず扱える
- 型を SQL の検索条件に明示できる
- frontmatter のフィールド名を固定せずに済む
- Markdown と frontmatter を正本としたまま、SQLite 側で検索を完結できる

日付と日時は SQLite の専用日時型を使わず、比較可能な ISO 8601 文字列として保持する。日時は UTC に統一し、タイムゾーン表記の違いによる比較の曖昧さを避ける。

## 結果

値カラムが増え、投入時に YAML 値を型ごとに変換する処理が必要になる。また、型ごとに検索インデックスを作る必要がある。これは検索の正確性と将来の範囲検索を優先したコストとして受け入れる。

文字列連結した単一の検索値に全てを押し込む案は採用しない。区切り文字、エスケープ、型変換、数値の辞書順比較を自前で扱う必要があり、SQLite の型別検索を活かせないためである。
