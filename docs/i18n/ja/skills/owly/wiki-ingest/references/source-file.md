# ソースファイル取り込みリファレンス

`wiki-ingest`をソースファイルに適用するときに読む。

## ソースの保存

- ソースが設定されたrawディレクトリ配下にある場合は、そのパスを維持する。
- それ以外の場合は、Wikiのraw領域へコピーしてから知識を作る。
- 安定した衝突しないパスを選ぶ。既存ファイルの置換は事前に確認する。
- 保存したパスをページの`sources`メタデータに記録する。
- 保存したソースファイルのSHA-256をソース追跡用に計算する。これは出典情報であり、ソースを読む代わりにはならない。

## 蒸留

ソースの話題、主張、登場する対象、役に立つ関係を把握できる範囲を読む。ソースを丸写ししたり、段落ごとにページを作ったりしない。

- Markdown・テキスト: 直接読み、重要な見出しと主張を保持する。
- PDFなどのバイナリ: 利用可能な文書リーダーで読む。読めない場合は推測せず制約を報告する。
- 大きなファイル: 有界な部分に分けて読み、ページとリンクに必要な情報だけ保持する。
- 既存ページと矛盾する場合は、出典を明示して両方の主張を保持し、矛盾を報告する。勝手に一方を正解にしない。

## ページの選択

書き込む前に、同じ主題を扱う既存ページを検索する。ソースが証拠や新しい理解を加える場合は既存ページを更新する。適切な既存ページがない場合だけ新規ページを作る。

作成・更新するページには、設定されたタイプに合うfrontmatterと、次のようなソースレコードを付ける。

```yaml
sources:
  - path: raw/inbox/example.md
    sha256: <保存したソースファイルのsha256>
    origin: https://example.com/optional-origin
```

`owly schema`に定義されたタイプとフィールドを使い、スキーマを勝手に作らない。

## グラフへの統合

トップレベルの入口なら`entrance.md`から、それ以外なら最も関連する既存ページからリンクする。関連する概念、対象、ソース由来ページをリンクで接続する。孤立診断を避けるだけの推測リンクは追加しない。
